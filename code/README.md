# 知学 · 智慧学习平台 Demo

本地 Python 服务 + 原生 HTML/CSS/JavaScript。支持教师发布课程、学生学习与答题、自动评分、持久化学习记录，以及师生上传课程视频并提取课件图片、PDF 和音频。提取完成后，可通过 DeepSeek API 生成课程总结网页，在新标签页阅读。

## 启动

需要 Python 3.10+。Windows 双击 `run.bat`，或者在本目录执行：

```powershell
python run.py
```

启动脚本会创建本目录的 `.venv`，使用 **清华大学 PyPI 镜像**安装依赖和 FFmpeg：

```text
<项目虚拟环境的 Python> -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

首次安装需要联网；之后依赖未变化时直接启动，不会重复安装。安装失败不会写入成功标记，重新运行会再次尝试。服务只监听本机，默认地址 `http://127.0.0.1:8765`，占用时自动尝试后续端口，以启动窗口的地址为准。保留启动窗口，按 `Ctrl+C` 停止。

```powershell
python run.py --check                 # 准备并检查依赖后退出
python run.py --no-browser --port 8800 # 指定端口，不自动打开浏览器
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

macOS/Linux 的虚拟环境 Python 位于 `.venv/bin/python`。

## 账号、密码与登录

首页提供登录、注册和演示账号表。学生与教师都可以注册，账号为 3–32 位字母/数字/下划线（不区分大小写），密码为 6–128 个字符，姓名为 1–30 个字符。

| 身份 | 姓名 | 账号 | 初始密码 |
| --- | --- | --- | --- |
| 教师 | 王老师 | teacher1 | Teach123! |
| 教师 | 李老师 | teacher2 | Teach456! |
| 学生 | 张同学 | student1 | Learn123! |
| 学生 | 陈同学 | student2 | Learn456! |

点击“填入账号”→“登录”→“进入工作台”，会打开新标签页，登录页保留供继续登录其他账号。新注册账号也提供工作台入口。教师和学生、两个不同学生都可以在同一浏览器同时登录，标签页互不切换身份。

- **账号文件：`data/accounts.json`**。按照本项目的课堂演示要求，账号密码以明文保存在此文件，不写入 LocalStorage 或 SessionStorage。文件首次启动自动生成，后续启动保留注册信息和修改后的密码。
- 账号管理页面支持验证原密码后修改密码；退出登录会撤销当前登录会话。
- 浏览器仅使用 HttpOnly Cookie 保存随机会话标识。页面 URL 的 `account` 是公开账号 ID，不是密码或登录凭证；服务端验证 Cookie 决定真实身份，不能通过修改 URL 或角色请求头取得教师权限。
- 会话有效期 12 小时，服务重启后需重新登录；账号、课程、成绩和提取结果不丢失。
- 首页只展示预置演示账号的当前密码，不公开自行注册的账号密码。请使用演示专用密码。
- 教师只管理自己的课程并查看对应提交；学生只查看个人学习记录。各账号的视频任务独立保存，教师将自己的提取任务关联到已发布课程后，登录用户可以访问该课程资源。

旧版数据会自动补上账号归属：原来的王老师课程、视频归到 `teacher1`，张同学的成绩归到 `student1`，已有内容和文件保留。

## 多标签页与验收流程

工作台、课程学习、课程创建/编辑、视频提取、学习记录、账号管理等模块入口均为新标签页链接。表单保存、评分反馈和任务进度在所属页面内更新。工作台和记录页重新获得焦点时自动刷新，也提供手动刷新按钮。

建议按以下顺序演示：

1. 使用 `teacher1` 登录并打开教师工作台，点击“创建课程”。
2. 保存课程草稿，打开“添加资源与练习”，添加至少一份资源、一道单选题，点击发布。
3. 回到保留的登录页，使用 `student1` 登录，打开学生工作台。
4. 点击课程的“开始学习”，在新标签页查看资料、作答并提交。
5. 查看即时得分、正确答案和已保存提示，打开“学习进度”查看个人记录。
6. 回到教师工作台或“学习情况”页，查看学生姓名、提交时间、正确题数和成绩。
7. 使用 `student2` 登录，验证其个人记录与 `student1` 独立。

课程资源可以先登记说明；要提供实际可阅读的课件，请关联已完成的视频提取任务。默认附带 Python 示例课程与三道练习题。

## 学生与教师的视频提取

双方工作台均提供“上传与提取视频”入口：

1. 选择或拖入视频，确认后上传到本机项目目录。
2. 选择细致/均衡/精简模式，查看上传、识别、导出进度；支持取消。
3. 完成后预览课件页面，下载 JPG 压缩包、图片式 PDF 和 MP3 音频。
4. 教师可以在课程编辑页刷新提取结果，将完成的任务关联为课程资源；学生可直接打开课件。
5. 点击“生成课程总结”，查看准备截图、等待 DeepSeek、检查与保存的进度；完成后点击“查看课程总结 ↗”，在新标签页阅读。

视频提取只在本机运行，不需要 API Key、Node.js 或显卡；可选的 AI 总结需要互联网和 DeepSeek 密钥。每个任务输出位于 `data/jobs/<任务 ID>/`：

```text
job.json       # 账号归属、提取与总结状态、页码、时间和 API 用量（不含密钥）
slides/        # 去重后的原尺寸 JPG
slides.pdf     # 图片式课件 PDF
slides.zip     # 全部 JPG
audio.mp3      # 第一条音轨；无音轨时不生成
summary.html   # 点击生成且成功后才出现；DeepSeek 返回的静态总结网页
```

源视频的上传副本在任务完成、失败或取消后删除，原始视频不受影响；生成资料可在刷新或重启后继续下载。保存位置由浏览器下载设置决定。

适合 PPT/讲义占主要画面且有稳定停留的录像，使用 FFmpeg 缩略图流、帧差和感知哈希提取稳定页面。重复页面保留首次结果；动画、鼠标和摄像头可能造成多页或漏页，请核对预览。最多 600 页、单文件上限 8 GB，同一服务一次处理一个视频。无稳定页面时使用间隔截图并提示；无音轨时仍会生成图片和 PDF。

**提取产物是 JPG/PDF/MP3，不是可编辑的 PPTX。已接入基于截图的 AI HTML 总结及网页内的折叠自测题；语音转文字、音频理解、将 AI 题目导入课程题库并计分尚未接入。**

`VIDEO_DEMO_FFMPEG` 可指定 FFmpeg 路径，也可放入 `bin/ffmpeg.exe`；否则优先使用 PATH，再使用依赖中的 FFmpeg。`VIDEO_DEMO_DATA` 可更改任务目录，账号和学习数据随之存放在该目录的上级目录。

## DeepSeek 课程总结（本次新增）

### 配置密钥

Windows 可在“编辑账户的环境变量”中新增用户变量 `DEEPSEEK_API_KEY`，值为自己的 DeepSeek API 密钥。也可以在 PowerShell 中配置用户变量：

```powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "填入你的密钥", "User")
```

仅希望当前启动窗口使用时：

```powershell
$env:DEEPSEEK_API_KEY = "填入你的密钥"
python run.py
```

每次点击生成时，后端依次检查：**服务进程环境变量 → Windows 用户变量 → Windows 系统变量**，使用首个非空值。用户变量在点击时读取，因此服务启动后新增用户变量也能生效；如果修改了服务已继承的旧值，应重启服务，避免旧值优先。macOS/Linux 使用进程环境变量。

密钥只在后端读取，不发送到浏览器、不写入任务文件或 LocalStorage。未配置时浏览器会弹窗说明，不会发送 API 请求。

### 使用与进度

1. 登录学生或教师账号，打开“视频提取”，上传视频并等待 JPG 提取完成。已有的成功任务也可使用。
2. 在结果页点击“生成课程总结”。页面会说明截图将发送给 DeepSeek，并使用该账户的 API 额度。原始视频和 MP3 不上传给 AI。
3. 准备截图显示实际处理张数与进度；等待 API 时显示动态进度条和已等待时间；收到结果后显示检查、保存，成功后到达 100%。等待 API 时不伪造完成百分比。
4. 点击“查看课程总结 ↗”，新标签页显示 DeepSeek 生成的概览、知识点、截图来源、易混点及折叠自测题。总结仅依据画面，未分析音频，内容应结合原课核对。
5. 生成期间可刷新或离开页面，但应保持 Python 服务运行。生成结果和状态保存在任务目录；重启后重新登录即可查看。服务中断的生成任务会标记为“已中断”，可以重试。

相同任务的重复点击不会重复调用 API，已生成的结果直接复用；同一服务一次生成一个总结。只有任务所有者能发起生成，查看沿用提取资源的访问权限。

### 错误处理与实现范围

- 缺少密钥、密钥失效、余额不足、权限不足、限流、服务异常、网络故障、超时、截图丢失或存储失败，均提供中文错误说明。生成失败和进度连接失败会在浏览器弹窗，同时保留页面提示。错误不覆盖已有 JPG/PDF/MP3，可在排除原因后重试。
- 后端固定使用 `https://api.deepseek.com/chat/completions` 和支持图片输入的 `deepseek-flash`，以 Base64 JPG 调用。每张发送副本最长边缩至 1600 像素，原图不修改；最多 600 张，请求限制在 45 MiB 内，超过时提示精简或拆分视频。连接/读取超时为 180 秒，网络恢复后不会自动重复付费请求。
- 总结正文由 **DeepSeek 实际返回**。若请求失败、内容截断或 HTML 不合格，显示失败，不使用本地模板或其他模型冒充生成结果。
- 只接收静态 HTML/CSS；禁止脚本、事件属性、外部资源等内容，并以独立 CSP 限制页面。服务展示时仅将相对截图路径转换为有账号权限校验的图片地址，正文不改写。
- 当前只生成 HTML 总结；可使用浏览器打印功能另存 PDF。网页自测题不自动计入课程成绩或学习记录。

### 自测记录（2026-11-01）

- 自动化测试：`python -m unittest discover -s tests -v`，**29 项通过**。覆盖原有课程与提取流程，以及密钥来源、API 错误、失败重试、重复请求、账号隔离、HTML 限制、服务中断恢复与磁盘写入失败。
- 真实端到端：Chrome 登录 `student1` → 上传仓库根目录的 `example.mp4` → 提取 **9 张 JPG** → 点击生成 → **真实调用 DeepSeek** → 等待期间刷新恢复 → 新标签页查看。总结生成耗时 **31.9 秒**，用量 **13,116 tokens**；截图正常加载，自测答案可展开，390px 手机宽度无横向溢出。
- 重启服务后，已保存的总结仍可查看，无需再次调用 API。浏览器另以模拟故障验证 **7 种弹窗场景**：缺少密钥、密钥无效、余额不足、服务异常、API 超时、提交连接失败、进度连接失败；错误场景不消费真实 API 额度。
- 自测产物保存在 `../experiments/feature-selftest/`：`result.json` 为真实流程结果，`error-tests.json` 为模拟故障记录，另有页面截图。真实任务 ID 为 `5f0bfe905c68466e8e43b540c21f04fd`，结果位于本目录 `data/jobs/<任务 ID>/summary.html`，可用 `student1` 从最近任务中打开。

## 代码结构与分工接口

```text
run.py / run.bat          # 虚拟环境、镜像安装、启动与环境检查
requirements.txt         # 运行依赖
demo/accounts.py         # 本地账号文件、注册、登录、改密、会话验证
demo/app.py              # HTTP API、角色权限、课程、答题与学习记录
demo/jobs.py             # 视频任务、账号归属、持久化、取消与恢复
demo/media.py            # 本地 JPG/PDF/ZIP/MP3 提取算法
demo/summaries.py        # DeepSeek 密钥读取、图片请求、HTML 检查与总结任务
web/index.html           # 页面入口与视频工作台模板
web/app.js               # 登录、工作台、独立页面、课程与记录交互
web/video.js             # 上传、提取/总结进度、错误弹窗、预览和下载
web/style.css            # 界面样式与响应式布局
tests/test_demo.py       # 真实 HTTP + FFmpeg 集成测试
tests/test_bootstrap.py  # 镜像安装、复用与失败重试测试
tests/test_summaries.py  # 总结权限、密钥、API 故障、恢复与安全验证
data/accounts.json       # 明文演示账号和注册账号
data/learning-platform.json # 课程及学习记录
```

四人后续可分别主责：①用户/角色/工作台，②课程资源与教师发布，③学习活动/练习反馈/记录与统计，④视频处理与后续 AI API 学习能力。各自围绕对应模块补充需求、设计、实现和测试；模块通过当前 HTTP API 和账号 ID 互通。

页面提取方法参考 [BIT 项目](https://github.com/lankerr/BIT_yanhe_download_2026)，此 Demo 使用独立的简化实现。
